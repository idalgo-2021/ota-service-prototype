# OTA-бэкенд

Go API для каталога жилья и продуктов, бронирований, заказов, отзывов, статей и кабинетов пользователей. PostgreSQL с PostGIS — источник данных OTA.

## Основные флоу

- **Публичный каталог:** поиск и карточки объектов и продуктов, доступность жилья, справочники, статьи и опубликованные отзывы.
- **Клиент:** регистрация и вход, профиль, бронирования, заказы, отзывы и чат с ИИ-ассистентом.
- **Отельер:** управление назначенными объектами, номерами, изображениями и видео; работа с бронированиями, отзывами и сообщениями.
- **Сотрудники:** управление каталогом, заказами и бронированиями, пользователями, справочниками, тегами объектов, статьями и модерацией отзывов. Разделение полномочий зависит от роли.
- **Статьи:** сотрудники создают и редактируют статьи, публикуют и снимают их с публикации. Публичная выдача показывает только опубликованные статьи, новые статьи по умолчанию сняты с публикации.

## Роли

| Роль | Доступ |
| --- | --- |
| `user` | Профиль, бронирования, заказы, отзывы, чат ассистента |
| `hotelier` | Кабинет и назначенные объекты, связанные бронирования и сообщения |
| `manager` | Операционные административные функции и модерация |
| `admin` | Полный административный доступ, включая пользователей и справочники |
| `ai_robot` | Ограниченные AI-ручки для импорта отзывов и данных объектов |

Гости могут просматривать публичный каталог и обращаться к ассистенту без входа. Роль пользователя не даёт административного доступа.

## JWT и ИИ-ассистент

- Авторизация в системе базируется на JWT-токенах (`Authorization: Bearer <token>`).
- Публичные ручки без авторизации доступны всем гостям сервиса.
- Взаимодействие с ИИ-ассистентом (отдельный сервис) выстроено так, что OTA-бэкенд проксирует запросы фронтенда на HTTP API ИИ-сервиса (и обратно). При этом, если пользователь имеет валидный JWT-токен, то он передаётся вместе с запросом в ИИ-сервис (где ИИ-ассистент с помощью этого токена может обращаться к клиентским эндпоинтам API OTA).
- ИИ-сервис (его подкомпоненты импорта данных для саммаризации отзывов и детекции разочарования) запрашивает через API OTA специализированные защищённые эндпоинты, используя выделенную сервисную роль `ai_robot`. Также ИИ-сервис использует общедоступные эндпоинты.

## Система статусов, реализованных в OTA

Поскольку в OTA реализован ряд характерных для подобного рода приложений процессов, некоторые составляющие их сущности имеют систему статусов. Обработка статусов подразумевает их изменение при действиях пользователей, а также при выполнении регламентных заданий (например, закрытие «зависших» заказов, незавершённых отзывов и т. д.).

> **Важно.** Сейчас регламентные задания по расписанию не запускаются автоматически (cron/worker), но для них созданы соответствующие консольные утилиты ручного запуска.

- **Заказ:** (подбор продуктов клиентом из каталога) `pending` → `confirmed` → `fulfilled`; из `pending` или `confirmed` можно перейти в `cancelled`. Просроченные `pending`-заказы закрывает утилита обслуживания.
- **Бронирование:** (основная функция OTA-приложения — бронирование жилья) `confirmed` → `checked_in` → `completed`; отмена переводит активное бронирование в `canceled`.
- **Отзывы об объектах и продуктах:** (обработка отзывов двух видов — на бронирования и на заказанные продукты) `draft` → `pending_moderation` → `approved` или `rejected`. Скрытие опубликованного отзыва хранится отдельным флагом.

Ещё несколько сущностей, имеющих не статусы, но важные бинарные характеристики:

- **Объект:** доступность в каталоге задаётся `is_active`.
- **Статья:** публикация задаётся `is_published` и `published_at`.
- **Сообщение отельеру:** `new` → `processed`.

## API и документация

- OpenAPI-файлы — в `docs/`
- Swagger UI: http://localhost:8080/swagger/index.html

Сервисные эндпоинты:
- `GET /health` — проверка работоспособности

## Настройка и локальный запуск

Все команды выполняются из каталога `backend/`. Для работы требуются Go 1.25+, Docker Compose и GNU Make.

```bash
make setup
```

Команда копирует `.env.example` в локальный `.env` (если файла ещё нет). Бэкенд полностью автономен: проверяются только параметры самого бэкенда (`POSTGRES_PORT`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`), `JWT_SECRET` и порт сервера. Настройки `AI_SERVICE_BASE_URL` и `AI_INTERNAL_API_KEY` указываются здесь же в `.env` и требуются исключительно в том случае, если вы хотите проксировать запросы к внешнему ИИ-сервису. Никаких чужих файлов (в т. ч. `ai-service/.env`) бэкенд не читает и не требует.

### Вариант 1. Локальная разработка (API в Go, БД в Docker):

```bash
make db-up     # запустить только базу данных PostgreSQL с PostGIS (порт 5433 или 5432)
make migrate   # применить миграции к базе данных
make run       # запустить HTTP API локально (Ctrl+C для остановки)
make down      # остановить базу данных и освободить ресурсы
```

### Вариант 2. Запуск целиком в Docker (БД и API):

```bash
make build     # собрать Docker-образ бэкенда
make up        # запустить базу данных, применить миграции и запустить API в контейнерах
make logs      # смотреть логи всех контейнеров бэкенда
make down      # остановить все контейнеры сервиса
```

API будет доступен на `http://localhost:8080`.

### Загрузка демо-данных (seed-скрипты)

Для полной инициализации базы данных и наполнения её демо-данными выполните:

```bash
make bootstrap
```

Команда `make bootstrap` последовательно:
- запускает PostgreSQL (`make db-up`);
- применяет миграции схемы БД (`make migrate`);
- накатывает seed-скрипты каталога, пользователей, статей, тегов, отельеров и заказов (`make seed`);
- пересчитывает расстояния объектов до центров локаций (`make maintenance-recalculate-listing-distances`);
- пересчитывает рейтинги объектов по опубликованным отзывам (`make maintenance-refresh-listing-ratings`).

Либо можно отдельно запустить только загрузку базовых seed-скриптов:

```bash
make seed
```

## Утилиты обслуживания и регламентные команды

Все команды выполняются из каталога `backend/`. Они могут запускаться как вручную разработчиком, так и через планировщик cron.

| Команда | Назначение |
| --- | --- |
| `make db-up` / `make db-down` | Запустить / остановить контейнер PostgreSQL PostGIS |
| `make db-logs` | Смотреть логи контейнера базы данных |
| `make db-shell` | Открыть интерактивную консоль `psql` в контейнере БД |
| `make migrate` / `make migrate-rollback` | Применить миграции схемы / откатить последнюю миграцию |
| `make seed` | Загрузить стандартные демо-данные (пользователи, объекты, продукты, статьи) |
| `make bootstrap` | Полная инициализация: запуск БД, миграции, seeds и пересчёт метрик |
| `make maintenance-expire-orders` | Закрыть просроченные заказы со статусом `pending` |
| `make maintenance-review-drafts` | Создать черновики отзывов по завершённым услугам и закрыть просроченные черновики |
| `make maintenance-recalculate-listing-distances` | Пересчитать расстояния от объектов до центров локаций |
| `make maintenance-refresh-listing-ratings` | Пересчитать рейтинги объектов по опубликованным отзывам |
| `make maintenance-import-review-summaries` | Импортировать готовые саммари отзывов из ИИ-сервиса в OTA |
| `make maintenance-import-disappointment-analyses` | Импортировать результаты анализа разочарований из ИИ-сервиса в OTA |
| `make maintenance-sync-disappointment-notifications` | Сформировать и обновить сводные уведомления для отельеров |
| `make swagger` | Перегенерировать OpenAPI/Swagger документацию |
| `make test` | Запустить тесты Go |
| `make lint` | Проверить код линтером (`go vet`) |

### Интеграция с ИИ-сервисом

**1. Импорт саммари-сводок по отзывам об объектах недвижимости:**

Системой предусмотрена загрузка готовых саммари-сводок по объектам недвижимости, сгенерированных ИИ-сервисом. Для синхронизации выполните:

```bash
make maintenance-import-review-summaries ARGS="--page-size=250"  # размер страницы от 1 до 500 (по умолчанию 100)
```

**2. Импорт результатов детектора разочарований и отправка уведомлений отельерам:**

Для импорта результатов аналитики и рекомендаций из ИИ-сервиса в базу OTA выполните:

```bash
# 1. Загрузка данных анализа в локальную таблицу БД
make maintenance-import-disappointment-analyses

# 2. Формирование уведомлений отельерам по закреплённым за ними объектам
make maintenance-sync-disappointment-notifications
```

### Дополнительные CLI-команды

Дополнительные низкоуровневые утилиты (запускаются из каталога `backend/`):

- `go run ./cmd/maintenance recalculate-listing-distances --all` или `--location-id=...` — пересчёт расстояний для всех или конкретной локации.
